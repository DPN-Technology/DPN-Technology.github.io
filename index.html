03D // CAPTURE OPERATIONS + RUN INTELLIGENCE

Turn source proof into
repeatable runtime evidence.

The Capture Factory detects repo-native screenshot harnesses and manual GitHub Actions workflows. v3.5 adds an on-demand public workflow-history scan so installed automation, the latest execution result and committed runtime evidence remain three separate facts.

FACTORIES INSTALLED—workflow + repo-native capture harness discovered
READY ON HOSTED RUNNER—manual factory can run on GitHub-hosted infrastructure
RUNTIME MANIFESTS—committed evidence manifests discovered
PRODUCTS WITH ACTUAL VISUALS—mapped actual capture/output evidence
SELF-HOSTED REQUIRED—requires matching private runner capability
NOT YET AUTOMATED—public repos without the standard factory
EXECUTION POLICY MANUAL DISPATCH ONLY

Capture workflows are intentionally not triggered on every push. Use each card’s RUN FACTORY link to open the exact GitHub Actions workflow, choose Run workflow, and keep commit_results=true when you want successful captures committed as public evidence.

ON DEMAND // NOT CHECKED

Run history is queried only when requested so the Command Center does not spend public GitHub API budget on Actions history during every page load. A successful workflow run is execution evidence, not runtime proof; the standard manifest and image artifacts are still required.

LAST RUN SUCCEEDED—latest manual capture run concluded successfully
LAST RUN FAILED—latest manual capture run needs attention
RUNNING / QUEUED—latest capture workflow has not completed
NO RUN DISCOVERED—public API returned no workflow_dispatch run

03E // RUNTIME EVIDENCE AUTO-INGEST

When the real capture lands,
the Command Center can show it.

Committed capture manifests are fetched from their originating public repositories. Only validated image files inside docs/evidence/runtime/ are accepted, and every card retains the producing repository, manifest metadata and data-boundary disclosure.

VALID MANIFESTS—validated standard runtime evidence manifests
RUNTIME ARTIFACTS—accepted public image artifacts
PRODUCTS REPRESENTED—repositories with accepted runtime evidence
REJECTED / UNREADABLE—manifest failed validation or could not be fetched
AUTO-INGEST POLICY PUBLIC · VALIDATED · SOURCE-BOUND

Auto-ingest does not copy files into the Command Center repository. Images remain hosted by the product repository and are displayed only after the manifest passes path/type/schema checks. No manifest means no automatic runtime-evidence claim.
